# ARTY S7 スタンドアローン w11：RP07 設計メモ

## 目的

実機動作確認済みの sys_w11a_as7 を、PC 上のバックエンドなしで利用可能にする。
目標は、ARTY S7 1 枚で動く、構成を絞った高性能な PDP-11/70 である。
最初に実現する構成は、既存の 3.75 MiB DDR3 主記憶、基板上の FT2232
USB-UART を使う単一 PDP-11 コンソール（DL11）、PMOD 接続の microSD カード、
およびカード上の RP07 互換 raw ディスクイメージ 1 台分である。

提供済みの 2.11BSD RP07 起動イメージをエンドツーエンドの受入試験に使用する。
この作業では OS イメージを新規作成・再配布しない。

ディスクの見かけだけを RP07 にしない。RP06 イメージを大容量の仮想
ディスクへ置く方式ではなく、RP07 の幾何を実装する。

| 項目 | 値 |
| --- | ---: |
| シリンダ数 | 630 |
| 1 シリンダ当たりのトラック数 | 32 |
| 1 トラック当たりのセクタ数 | 50 |
| 1 セクタ当たりのバイト数 | 512 |
| 総セクタ数 | 1,008,000 |
| 容量 | 516,096,000 bytes（約 492 MiB） |

SD カード上の媒体形式は固定位置のセクタ単位 raw イメージとする。FAT、
パーティションテーブル、ホストのファイルシステムには依存しない。

## 単純性と性能の原則

- CPU、MMU、既存 DDR3 コントローラ、CPU キャッシュは w11 の実装を維持する。
- 初版の周辺機器は、単一 DL11 と単一 RP07 だけに限定する。
- RP07 は RBus/rlink を経由せず、SD ブロック層から主記憶へ直接 DMA する。
- DMA は 16-bit の逐次リモートアクセスではなく、連続ワードをまとめて
  転送できるバースト方式にする。
- SD は単一セクタ操作だけでなく、連続セクタの複数ブロック read/write を
  使える構造にする。起動に必要な単一セクタ操作を先に実装する。
- CPU の通常のメモリ要求を最優先とし、DMA は CPU の停止時間を最小化する。
- 性能は推測で判断せず、CPU クロック、DMA 転送量、SD 実効転送量、OS 起動時間を
  ベースラインと比較して評価する。

## PDP2011 の参照方法

PDP2011 は ARTY S7 と Pmod SD で OS 起動できる実績を持つため、動作する
参照実装として活用する。ただし、PDP2011 のソースコード、RTL の断片、状態機械、
制約ファイルを w11 へコピーまたは派生させない。

参照対象は次に限定する。

- Pmod SD の実際の接続、必要な信号、電圧、起動時の挙動。
- SD カード初期化、単一/連続セクタ転送、異常時の外部から見える振る舞い。
- OS 起動までの操作手順、カード形式、実効転送量、安定性。
- ARTY S7 上で確認すべき波形、LED 表示、reset、カード未装着時の観測項目。

w11 側の RTL、XDC、テストベンチ、設計文書は w11 の構造と公開可能な仕様に
基づいて独自に作成する。PDP2011 から得た観測・要件は、コピー元を含まない
日本語の検証メモとして記録する。

## 現在の ARTY S7 のデータ経路

```text
FT2232 UART -> rlink_sp2c -> RBus -> pdp11_sys70 -> IBus -> ibdr_maxisys
                                              \\-> cache/MIG 経由で DDR3
```

ibdr_maxisys には ibdr_rhrp が入っている。これは RHRP/RP のレジスタと
割込みを扱うリモートフロントエンドである。PDP-11 側がコマンドを受け付けると
RB_LAM_RHRP をアサートし、外部バックエンドが媒体 I/O、メモリ転送、
リモート IBus レジスタ更新を担当する。

リモートアクセスは次の経路を使う。

```text
RBus アドレス 0x4xxx -> pdp11_core_rbus -> IB_MREQ.racc = 1 の IBus 要求
```

pdp11_core_rbus は制御ポートを通したメモリ read/write も提供する。これは
現行バックエンドの転送経路である。本開発ではこの経路を通常運用に使わず、
CPU と DMA を正しく調停するローカルの主記憶アクセス経路を追加する。

## 公式ロードマップとの照合

w11 の公式ロードマップはスタンドアローン化を放棄していない。長期目標として、
「追加の w11a CPU を CIOP（コンソール兼 I/O プロセッサ）として動かし、
バックエンドサーバなしで運用するスタンドアローンシステム」を明記している。

これは、PDP-11 CPU が LAM を出し、CIOP が RBus を直接マスタとして使って
コンソールおよび媒体 I/O を処理する構成と読める。RBus は公式アーキテクチャ
文書でも、他のプロセッサへの直接 16-bit メモリマップド接続に使用できると
説明されている。

本開発では、この CIOP 案を採用しない。目標は、ARTY S7 1 枚の FPGA 内で
完結する直接的なスタンドアローン化である。追加 w11a CPU、外部 FPGA/基板、
PC バックエンド、通常運用時の rlink は使わない。

## 採用する直接実装方針

既存の ibdr_rhrp はリモートフロントエンドであるため、これをバックエンド
互換の状態機械で延命しない。RP07 用には、PDP-11 側から見える CSR、割込み、
エラー状態、機種コードを互換にしたネイティブ RHRP/RP07 コントローラを
新設する。既存 ibdr_rhrp はレジスタ仕様および試験の参照に使う。

```text
PDP-11 CPU -- IBus -- ネイティブ RHRP/RP07 -- SD ブロック層 -- PMOD microSD
                         |
                         +-- ネイティブ DMA -- 主記憶キャッシュ/DDR3

FT2232 USB-UART -- ネイティブ DL11 -- IBus
```

最大の設計課題は、既存の単一マスタ IBus を保ちつつ、ディスクコントローラが
PDP-11 主記憶へ DMA する正規の経路を追加することである。この経路は RBus の
バックエンド操作を内部再現するものではなく、CPU のメモリ要求と調停される
ローカル DMA インターフェースとして設計する。

通常のスタンドアローン構成から rlink を除く。デバッグ専用ビルドで rlink を
残す場合も、ネイティブ RHRP/RP07 および DL11 のデータ処理には関与させない。

## 作業項目と判定基準

### 2026-09-27 実装・実機確認の記録

専用ディレクトリ `rtl/sys_gen/w11a/artys7_standalone` に、CPU 優先の
主記憶調停器、DMA 書込み後のキャッシュ無効化、および Arty S7 用の
DDR3 自己診断トップを追加した。既存の `sys_w11a_as7` トップは変更していない。
自己診断は DDR3 の 32-bit ワードアドレス `0xC0000` に対し、DMA で
`0x11223344` を書き、キャッシュ経由で上下 16 bit を読み、次に
`0xA5C35A3C` を DMA 書込みして無効化後の再読出しを比較する。さらに
DMA 経路で 32 bit 全体を読み戻し、byte enable `0101` で下位と上位の
各 1 byte だけを書き換える。残る byte を保持した結果 `0xA5E15A7E` を
キャッシュ経由と DMA 経由の両方で比較する。

- Vivado 2022.1、xc7s50csga324-1 で合成・配置配線・bitstream 生成が成功。
  最終 WNS +1.344 ns、WHS +0.030 ns、失敗エンドポイント 0。
- JTAG ケーブル `210352B0BF4AA` から FPGA の揮発性構成領域へ書き込み、
  `USR_ACCESS=0xdcb4d8ee` を確認した。
- USB UART `/dev/ttyUSB1`、115200 bps で合格文字 `P` を 20 文字連続受信した。
  自己診断トップでは LED2 も合格を示す。
- 使用 bitstream の SHA-256 は
  `5520e9a2bb3f5a07d469f2099d26a6688706a8a20d6d9dd309f999c1911f1e88`。
- 調停器単体の XSim 試験は 165 ns で完了し、CPU/DMA の同時要求、
  CPU 優先、保留 DMA の完了、部分 byte enable の転送を確認した。

この合格は、固定アドレスでの DMA 書込み・読出し、部分 byte enable、
CPU 形式のキャッシュ読出しを確認したもの。実際の PDP-11 CPU 実行中の競合、
連続転送、RP07 および SD カードは未確認である。タイミング報告には MIG 生成
制約内のクロック間 false path に関する TIMING-54 が 2 件残る。これは
制約を緩めず、対象が MIG 内部であることを確認して記録した。

CPU 結合の接続点として、`pdp11_sys70` の境界にキャッシュ無効化要求・応答を
追加した。既定入力は無効のため、既存の `sys_w11a_as7` はポートマップを
変更せずに Vivado の解析・展開を通る。専用の `w11_cpu_dma_path` では
`pdp11_sys70` の主記憶ポートと DMA を `w11_mem_arbiter` に接続し、
RBus 全体リセットを調停器とメモリ制御側へ渡す `MEM_RESET` も出力する。
この結合モジュールは実際の `pdp11_core` を含めて Vivado の解析・展開を
通過したが、CPU 実行中に DMA を同時動作させる機能試験はまだ行っていない。
次の試験では実際の CPU メモリ要求を波形と結果で確認する。

### RP07 レジスタ仕様（第1週の調査結果、2026-09-27）

既存の `rtl/ibus/ibdr_rhrp.vhd`（PDP-11 側のレジスタ）と
`tools/src/librw11/Rw11CntlRHRP.cpp`（バックエンド側の転送処理）を読み、
現行実装がどの順序で何を行っているかを整理した。ネイティブ実装では、
PDP-11 側から見える挙動はこの表に合わせ、バックエンドの処理は
ネイティブの DMA と SD ブロック層に置き換える。

#### レジスタ（RH70、ベース 176700、unit 0 のみ online）

| 番地 | 名前 | R/W | ネイティブ RP07 での内容 |
| --- | --- | --- | --- |
| 176700 | CS1 | rw | SC, TRE, DVA=1, BAE[1:0], RDY, IE, FUNC[5:1], GO。TRE=1 の書込みで CS2 のエラーを消去。IE と RDY を同時に 1 にするとソフトウェア割込み |
| 176702 | WC | rw | 語数の2の補数。完了時に `WC + 転送語数` |
| 176704 | BA | rw | バスアドレス下位 16 bit（偶数）。完了時に更新 |
| 176706 | DA | rw | TA[12:8], SA[5:0]。完了時に次のセクタを指す |
| 176710 | CS2 | rw | WCE, NED, NEM, PGE, MXF, OR=1, IR=1, CLR, PAT, BAI, UNIT[2:0] |
| 176712 | DS | r | ATA, ERP, PIP, MOL, WRL, LBT, DPR, DRY, VV, OM |
| 176714 | ER1 | rw | UNS, WLE, IAE, AOE, RMR, ILF |
| 176716 | AS | rw | ドライブ別 ATA。1 を書いたビットを消去 |
| 176720 | LA | r | 現在セクタ（SC[11:6]） |
| 176722 | DB | rw | データバッファ（保持のみ） |
| 176724 | MR1 | rw | 保持のみ |
| 176726 | DT | r | `020042`（可動ヘッド＋RP07 の型番 042）。RP07 は RM 型コントローラとして扱う |
| 176730 | SN | r | BCD `1137`（unit 0。下位桁は unit の補数。2.11BSD の SI/CDC 判定を避けるため） |
| 176732 | OF | rw | 保持のみ |
| 176734 | DC | rw | CA[9:0]。完了時に次のシリンダ |
| 176736 | HR | rw | RM 型の holding register |
| 176740 | MR2 | rw | 保持のみ |
| 176742 | ER2 | r | 0 |
| 176744 | EC1 | r | 0 |
| 176746 | EC2 | r | 0 |
| 176750 | BAE | rw | バスアドレス上位 6 bit（CS1.BAE と連動） |
| 176752 | CS3 | rw | WCO, WCE（CS2.WCE と CS3.WCO から生成）, IE |

幾何：CA 0〜629、TA 0〜31、SA 0〜49。LBA = (CA×32 + TA)×50 + SA。

#### 転送コマンドの順序（現行実装）

1. CPU が CS2（unit）、DC、DA、BA、BAE、WC を書き、最後に CS1 に FUNC と GO（通常は IE も）を書く。
2. `ibdr_rhrp` 側の検査（ネイティブでも同じ順序で行う）：
   - RDY=0 の間に転送機能の GO → CS2.PGE。
   - DCLR は即時実行。
   - ERP=1 のドライブに GO → ER1.ILF。
   - MOL=0 → ER1.UNS と ATA。
   - write 系で WRL=1 → ER1.WLE。
   - DC または DA が範囲外 → ER1.IAE。IAE または WLE の場合は ATA だけを立てて終了し、RDY は変えない。
3. 転送機能（READ 034、WRITE 030、WCD 024）では、RDY=0 にして CS2 のエラーを消去する。現行実装ではここで LAM を出してバックエンドへ引き渡す。
4. 転送の実行：
   - アドレス = BAE:BA（22 bit 物理アドレス。RH70 なので UNIBUS マップは使わない）。
   - 語数 = 65536 − WC。
   - LBA＋ブロック数がディスク末尾を越える場合は、転送を末尾で打ち切って ER1.AOE を立てる。
   - 最終ブロックが半端な write では残りを埋める。
   - WCD は、最初の不一致で CS2.WCE を立てて打ち切る。奇数語での不一致なら CS3.WCO も立てる。
5. 完了時の更新：
   - `WC += 転送語数`、`BA/BAE = 開始アドレス + 2×転送語数`。
   - DA と DC は「開始 LBA + 転送ブロック数」の CHS。
   - 必要ならエラービットを立て、RDY=1 にする。IE=1 なら割込み。
   - 転送前エラー（UNS/IAE/WLE/ILF）は、RDY=1 にしたうえで ATA により通知する。
6. SEEK、RECAL、SEARCH、PRESET、PACK、OFFSET、RETC、DCLR、UNLOAD は `ibdr_rhrp` 内で完結している。SEEK 系は PIP と遅延の後に ATA。

#### DMA 要件

| 項目 | 要件 |
| --- | --- |
| アドレス | 22 bit バイトアドレス（偶数）。`DMA_ADDR = addr[21:2]`。16 bit 単位の開始・終了は BE `0011`/`1100` で扱う |
| 長さ | 1〜65,536 語。途中の 32 bit 語はまとめて転送する |
| READ | SD → メモリ。最後の DMA 書込みの ack（キャッシュ無効化を含む）を受けてから RDY=1 と割込み |
| WRITE | メモリ → SD。半端なブロックは 0 で埋める（実機 RP と同じ） |
| WCD | メモリと SD を比較。メモリには書かない |
| NEM | 実装メモリ（3840 KiB）外や I/O ページへのアクセスで CS2.NEM を立て、そこで打ち切る |
| BAI | CS2.BAI=1 ならアドレスを増やさない（現行バックエンドは未対応。初版では PGE 扱いも可） |
| 性能 | 実機測定で DMA 最大レイテンシは書込み 63 サイクル、読出し 82 サイクル（75 MHz、ping-pong 試験中）。SD の読出し速度（約 1〜2 MB/s）に比べて十分速い |

#### 参照実装で見つけた注意点（ネイティブ実装では踏襲しない）

- `Rw11CntlRHRP::AddNormalExit` は CS2 の値（WCE/NEM）を `kRPER1` に書いている（654 行）。ER1 のリモート書込みではビット14が UNS、ビット11が WLE に当たるため、write check エラーや NEM が「UNS」や「WLE」に見える。WCO（ビット15）も失われる。
- バックエンドの範囲チェックは `ca > NCylinder()` で、1 つずれている。ただし `ibdr_rhrp` 側が先に `camax = 629` で検査するため、実害はない。
- 半端ブロックの write を `0xdead` で埋めている。実機 RP は 0 で埋める。

#### microSD PMOD と媒体配置（2026-09-27 決定）

- PMOD：Digilent Pmod MicroSD（410-380）を JD に装着する。3.3 V（LVCMOS33）の SPI モード。
- ピン（Digilent Arty-S7-50-Master.xdc Rev E で照合済み）：

  | JD | FPGA | 信号 |
  | --- | --- | --- |
  | 1 | V15 | CS（DAT3） |
  | 2 | U12 | MOSI（CMD） |
  | 3 | V13 | MISO（DAT0、プルアップ） |
  | 4 | T12 | SCLK |
  | 9 | T11 | CD（カード検出、プルアップ。0=装着、1=未装着。2026-09-27 に実機で確認） |

  DAT1/DAT2（JD7/JD8）は使わない。制約ファイルは
  `rtl/sys_gen/w11a/artys7_standalone/artys7_pmod_sd_jd.xdc`。
- カードを抜くと CD=1 になり、初期化は無応答（err 1）になる。試験用ブロック層は
  抜いても初期化済みフラグを消さないため、RP07 コントローラでは CD=1 を
  「未装着（MOL=0）」として扱い、再装着後は必ず再初期化する。
- RP07 イメージの開始 LBA：0（カード全体を raw イメージとして扱う）。
  利用者から特に指定がなかったため提案どおりとした。読出し専用の段階
  なので、必要なら後で変更できる。

### A. ネイティブ DMA 経路の試作

- CPU と DMA 要求を調停する主記憶アクセスインターフェースを定義する。
- キャッシュと DDR3/MIG に対する読出し、書込み、byte enable、完了応答を
  定義する。
- シミュレーションで、DMA が PDP-11 メモリの既知領域を安全に read/write
  できることを確認する。

判定基準：CPU 動作中でも DMA の read/write が完了し、キャッシュと主記憶の
内容が一致すること。

### B. SD ブロック層

- 使用する microSD PMOD と接続先を決めた後にのみ、ARTY S7 の PMOD
  ピン制約を追加する。
- SPI モードのカード初期化と、1 セクタ単位の read/write を実装する。
- カード未装着、タイムアウト、CRC/トークン、範囲外、書込み保護を扱う。
  初期版のデータバッファは 512-byte BRAM とする。

判定基準：シミュレーションでコマンドとエラー状態遷移を網羅し、実機で
既知セクタの read/write を確認できること。

### C. ネイティブ RHRP/RP07 コントローラ

- unit 0 の 1 台だけを online とし、DTE_RP07 と RP07 幾何を報告する。
- read、write、write check、seek、recalibrate、drive clear、preset と、
  起動に必要なエラー/状態遷移を実装する。
- CHS を固定 raw イメージの LBA に変換し、ネイティブ DMA 経路で転送する。

判定基準：レジスタ試験、セクタ DMA read/write 試験、最終 RP07 セクタでの
境界試験がシミュレーションで通ること。

### D. ローカルコンソール

- I_RXD/O_TXD に接続するローカル DL11 を実装し、標準のコンソール
  CSR/ベクタ、RX/TX 割込みを維持する。
- ストレージ故障時にも端末を使えるよう、RBus とは独立させる。

判定基準：rlink をインスタンス化せずに、ODT と DL11 の割込み駆動 echo が
USB シリアル端末で動くこと。

### E. 結合と実機受入

- 既存の sys_w11a_as7 は変更せず、専用のスタンドアローン ARTY S7
  トップレベルとビルド対象を作る。
- 電源投入、RP07 起動イメージの起動、ファイルシステム read/write、
  正常 shutdown、I/O 中の reset、カード未装着、書込み保護を確認する。
- 取り返しのつかない媒体を使う前に、使い捨てのカード/イメージで
  長時間 read/write 試験を行う。

判定基準：提供済みの RP07 2.11BSD イメージが、バックエンドプロセスおよび
rlink 通信なしで起動・動作すること。

判定基準を満たさない場合は、後続の機能追加を始めずに原因を解消する。
既存の sys_w11a_as7 を変更しないため、各段階の成果は専用ディレクトリと
専用トップレベルに追加する。

| 週 | 作業 | 成果物・完了条件 |
| --- | --- | --- |
| 第 1 週 | 現行 RHRP とバックエンドのトランザクションを追跡し、RP07 コマンド開始から完了までのレジスタ更新順を確定する。microSD PMOD の型番と使用コネクタも確定する。 | RP07 レジスタ仕様表、DMA 要件表、PMOD のピン割当案、テスト対象 RP07 イメージの開始 LBA を設計メモへ追記する。 |
| 第 2 週 | CPU とディスク DMA を調停する主記憶アクセス経路をシミュレーション環境へ追加する。 | CPU 動作中に DMA が既知メモリ領域を read/write でき、キャッシュ整合性試験が通る。 |
| 第 3 週 | ARTY S7 用 SPI 物理層と SD 初期化を実装する。まずカード初期化、CID/CSD 読出し、単一セクタ read を扱う。 | 実機でカードを識別し、指定 LBA の 512-byte セクタを読める。カード未装着とタイムアウトを検出できる。 |
| 第 4 週 | SD の単一セクタ write、512-byte BRAM バッファ、書込み保護、read/write のエラー処理を追加する。 | 使い捨て媒体上で既知パターンの read/write と長時間セクタ試験が通る。RP07 イメージはまだ書き換えない。 |
| 第 5 週 | ネイティブ RHRP/RP07 コントローラを実装する。unit 0 の RP07 状態、CHS-LBA 変換、seek/preset/drive clear、および read DMA を追加する。 | RP07 の先頭・中間・最終セクタを PDP-11 メモリへ DMA 読出しできる。範囲外アクセスは正しいエラー状態になる。 |
| 第 6 週 | write DMA、write check、割込み、リセット中断、エラー完了処理を追加する。 | RHRP レジスタ・割込み試験と、メモリ対 SD の read/write 比較試験が通る。 |
| 第 7 週 | ローカル DL11 を追加し、rlink を外した専用 ARTY S7 トップレベルを結合する。 | USB シリアル端末で ODT を操作でき、RHRP を通じて RP07 ブートブロックを読める。 |
| 第 8 週 | 提供済み RP07 2.11BSD イメージで起動・運用試験を行う。reset、カード未装着、書込み保護、長時間 I/O を検証する。 | PC バックエンドなしで 2.11BSD が起動し、read/write と正常 shutdown が完了する。 |

### 週ごとの確認事項

- 第 1 週の PMOD 選定が未完了なら、第 3〜4 週の実機作業は開始しない。
- 第 2 週でネイティブ DMA のキャッシュ整合性が確認できない場合は、SD 実装より
  先に主記憶アクセス経路を修正する。
- 第 5 週の read DMA が安定するまでは、RP07 起動イメージへの write を
  禁止する。第 6 週以降も、最初は複製イメージだけで write を試験する。
- 第 8 週の受入試験に失敗した場合は、新たな周辺機器を追加せず、
  RHRP、DMA、SD のいずれで失敗したかを波形とログで切り分ける。

## 技術項目と難易度

難易度は 1（低い）から 5（非常に高い）の 5 段階で示す。この表は、現時点では
w11 のソース構造と一般的な FPGA 設計上の依存関係から作った**暫定評価**である。
ARTY S7 上での本拡張を実装・測定した経験値ではない。第 1〜2 週の調査と試作の
結果に基づき、各項目の難易度と日程は更新する。

評価には RTL の記述量だけでなく、既存 w11 の動作を損なう危険、実機でしか
確認できない要素、PDP-11 周辺機器との互換性、性能目標を含める。対象は
ARTY S7-50 と Vivado のみであり、他 FPGA への移植性は評価対象に含めない。

| 技術項目 | 難易度 | 内容 | 主なリスクと確認方法 |
| --- | :---: | --- | --- |
| ARTY S7 専用 Vivado 構成 | 2 | 既存 sys_w11a_as7 を変更せず、専用トップレベル、XDC、Vivado ビルド対象を追加する。 | 制約・ライブラリの取り込み漏れ、タイミング悪化。既存設計との差分、合成、配置配線、タイミングで確認する。 |
| microSD PMOD 接続 | 2 | 選定した PMOD の SPI 信号、電源、カード検出を ARTY S7 に割り当てる。 | 型番、ピン番号、IO 電圧、カード検出極性。回路図、XDC、最小 SPI 試験で確認する。 |
| SD 初期化と SPI 物理層 | 3 | クロック分周、CMD0/CMD8/ACMD41、OCR/CSD、MOSI/MISO/CS を実装する。 | カード種別差、位相、応答待ち、信号品質。複数カード、波形、タイムアウト試験で確認する。 |
| SD セクタ・ブロック転送 | 4 | 起動用の単一セクタ転送に加え、性能用の連続複数セクタ read/write と BRAM バッファを実装する。 | トークン、CRC、書込み完了待ち、バッファ境界、実効帯域。既知パターンと連続転送量を実測する。 |
| SD 媒体保護と異常処理 | 3 | カード未装着、書込み保護、範囲外 LBA、タイムアウト、転送失敗を扱う。 | RP07 起動イメージの破壊。read-only、複製イメージ、電源断を含む試験で確認する。 |
| ネイティブ DMA 主記憶経路 | 5 | CPU とディスク DMA を調停し、キャッシュおよび DDR3 へ整合した read/write を行う。 | キャッシュ整合性、byte enable、22-bit アドレス、途中中断。CPU と DMA を同時動作させたメモリ試験と波形で確認する。 |
| 高性能 DMA スケジューリング | 5 | CPU の停止を抑えつつ、連続メモリ転送をバースト化する。 | CPU 性能低下、帯域不足、飢餓。CPU ベンチマーク、DMA 実効帯域、OS 起動時間を基準構成と比較する。 |
| ネイティブ RHRP/RP07 レジスタ | 4 | ibdr_rhrp を仕様参照に、CPU が直接操作する CSR、割込み、エラー状態、RP07 機種コードを実装する。 | ドライバが期待する副作用と reset 時の状態。既存 RHRP レジスタ試験を移植して確認する。 |
| RP07 アドレス変換 | 2 | cylinder、track、sector を 1,008,000 セクタの raw イメージ LBA に変換する。 | セクタ番号の起点、終端値、範囲外。境界値の単体試験で確認する。 |
| RP07 コマンド状態遷移 | 5 | seek、preset、read、write、write check、完了、エラー、割込みを 2.11BSD 互換に動かす。 | BSD 起動処理が期待する状態・エラーとの不一致。レジスタ試験、DMA 試験、RP07 起動試験で確認する。 |
| ネイティブ DL11 | 3 | FT2232 UART を DL11 の CSR、RX/TX バッファ、RX/TX 割込みへ直接接続する。 | ボーレート、受信オーバーラン、割込みタイミング。ODT と OS コンソールで確認する。 |
| reset と全体結合 | 4 | CPU/bus reset、SD エラー、カード抜去時に DMA と各状態機械を安全に停止・初期化する。 | バス停止、データ破損、復帰不能。各状態で reset と異常を注入する試験で確認する。 |
| RTL テストベンチ | 4 | RHRP、SD 応答、DMA、DL11、異常系の自動試験を構成する。 | 実機との差。SD モデルと実カードの双方で検証する。 |
| 実機受入と性能測定 | 4 | RP07 2.11BSD 起動、ファイル read/write、shutdown、長時間 I/O と性能を確認する。 | 再現しにくい媒体エラーと性能退化。複数カード、反復起動、基準値との比較で確認する。 |

最優先で解消すべき不確実性は、ネイティブ DMA 主記憶経路のキャッシュ整合性と
性能、および既存 ibdr_rhrp のレジスタ仕様をネイティブ RHRP へ移す際の
互換性である。
SD の SPI 通信は PDP2011 の実機実績によって ARTY S7 上での成立性が確認済み
だが、w11 側のネイティブ DMA 結合は本開発固有の課題である。

## 初版の対象外

- RP07 を複数台扱うこと。
- RK11、RL11、テープ、Ethernet、VGA、PS/2。
- FAT/exFAT の解釈、媒体の活線抜挿、利用者向け SD メニュー。
- PDP2011 の RTL をコピーまたは派生させること。

これらはネイティブ DMA 主記憶インターフェースと SD ブロック層が安定した後に
追加する。
